Designed for clarity

A simple answer to “what changed?”

Use it alongside your backups to catch unexpected changes before they disappear into the next copy.

01 / BASELINE

One or several folders

Keep a dated reference for local drives, external drives, and accessible network folders in one project.

02 / RECHECK

Hash every file again

Each check reads the file bytes and calculates SHA-256, even when size and modified time look unchanged.

03 / REVIEW

Clear history and reports

See additions, missing files, and changed hashes. Save an HTML report and choose when to trust a new baseline.

Three steps

Keep your own record.

Choose folders

Create a local project outside the folders you plan to scan. Add every archive location you want to track.

Make a baseline

Run the first scan after checking that your archive is in the state you want to trust.

Check later

Run another scan and open its report. If changes are intentional, you can explicitly trust a complete check.

What the result means

Evidence of changed bytes, with honest limits.

A matching hash means the bytes read at that path matched the trusted scan. A changed hash tells you where to investigate.

FileIntegrityTimeline does not identify the cause, recover files, or prove a backup can restore. A scan is not an atomic snapshot; files can change between checks.

Built for cautious use

  • Source files are opened for reading. The project database and reports are saved outside scanned folders.
  • Unreadable files or folders make the scan incomplete, so it will not claim files are missing.
  • Symbolic links are skipped. An unavailable root stops the scan.
  • Reports include full folder paths. Review them before sharing.
  • Large archives can take hours because every file is read again.
